# StudyMate — الموقع

## إعداد Firebase وApp Check

تهيئة مشروع `studymate-dev-a2766` ومفتاح reCAPTCHA Enterprise العام موجودة في `src/services/firebase.ts` وتعمل عند بدء الموقع. التسجيل والدخول واستعادة كلمة المرور في الموقع تستخدم Firebase Authentication. توليد Gemini لم يربط بعد. Storage مؤجل ويظل تخزين الملفات الحالي كما هو.

يجب تشغيل الخادم أيضًا من مجلد `backend` بالأمر `dotnet run --project StudyMate.Api`. إعداد Development يطبّق الترحيلات على قاعدة LocalDB المحلية عند البدء. الخادم يتحقق من توقيع رمز Firebase ومشروعه وصلاحيته وتأكيد البريد ثم يربط UID بمعرّف المستخدم في SQL. ينشئ الحساب الجديد كطالب، ويمكن ربط حساب طالب سابق مؤكد بنفس البريد مع الحفاظ على معرّفه وبياناته؛ يتوقف الربط عند تعارض الهوية أو حساب إدارة أو حساب غير مؤكد/معطل. عند الربط تُلغى الجلسات وروابط الحساب القديمة ويصبح الدخول عبر Firebase. تطبيق الجوال لم يُرحّل بعد؛ الحسابات المرتبطة تحتاج استخدام الموقع حتى يكتمل ترحيل الجوال.

للتجربة: أنشئ حسابًا من الموقع ببريد تملكه، وافتح رابط التأكيد الذي ترسله Firebase، ثم عد وسجّل الدخول. رسائل التحقق وإعادة تعيين كلمة المرور تستخدم صفحات Firebase المستضافة الافتراضية. جرّب تسجيل الخروج ثم الدخول وإعادة تحميل الصفحة. لا تُرسل كلمات المرور أو رموز التجربة في المحادثة.

تُحفظ جلسة Firebase لمدة جلسة المتصفح ويجدّد SDK رمز الدخول تلقائيًا. التحقق بالتوقيع لا يستعلم عن إلغاء الرمز لحظيًا من Firebase؛ قد يبقى الرمز الصادر صالحًا حتى انتهاء مدته (عادة ساعة). تعطيل الحساب في قاعدة StudyMate يمنع الطلب التالي مباشرةً. يلزم إضافة تحقق الإلغاء عبر Firebase Admin قبل اشتراط إلغاء فوري من لوحة Firebase. إعداد App Check الحالي يحمي خدمات Firebase المشمولة به؛ لا يفرض App Check على ASP.NET تلقائيًا.

عند تشغيل `npm run dev` وفتح الموقع على `localhost` أو `127.0.0.1`، يستخدم App Check وضع Debug. افتح أدوات المطور ثم Console وانسخ رمز `App Check debug token` الذي تطبعه مكتبة Firebase. سجله مباشرة في Firebase: App Check → Apps → قائمة التطبيق → Manage debug tokens → Add debug token. أعد تحميل الموقع بعد الحفظ. الرمز خاص بالمتصفح؛ لا تضعه في Git أو ترسله للمحادثة.

بناء الإنتاج يستخدم reCAPTCHA Enterprise دون تفعيل Debug. نطاق المفتاح المسجل هو `mariam2020abd-hash.github.io`؛ معاينة إنتاج على localhost ليست اختبارًا صالحًا لهذا المفتاح. نجاح البناء لا يثبت قبول App Check؛ يلزم اختبار التبادل الحي بعد تسجيل رمز التطوير.

إعدادات Firebase ومفتاح الموقع هنا عامة. لا تضف مفاتيح حساب الخدمة أو مفتاح Gemini السري إلى الواجهة. وجود `storageBucket` في التهيئة لا يفعّل التخزين أو الفوترة.

## النشر على GitHub Pages

ينشر الملف `.github/workflows/deploy-website.yml` الموقع عند رفع تغييرات `website` إلى `main`، ويمكن تشغيله يدويًا من Actions. يجب اختيار **GitHub Actions** من إعدادات المستودع **Settings → Pages → Source**.

رابط النشر: https://mariam2020abd-hash.github.io/StudyMate/

يضبط `vite.config.ts` مسار ملفات البناء إلى `/StudyMate/`، بينما يبقى التشغيل المحلي على `/`. عند تغيير اسم المستودع أو استخدام نطاق مخصص يجب تحديث هذا المسار.

مشروع React + React DOM + Vite مستقل. لا يعتمد على أي ملفات من تطبيق الجوال.

من هذا المجلد، باستخدام Node.js 22.13 أو أحدث:

```sh
npm ci
npm run dev
```

- `npm run typecheck`: فحص TypeScript.
- `npm run build`: بناء الموقع داخل `dist`.
- `npm run preview`: معاينة البناء محليًا.

الصفحات داخل `src/pages`، والمكوّنات داخل `src/components`، وحالة لوحة الطالب داخل `src/hooks`. البيانات والأنواع والألوان تخص الموقع وحده.

تبدأ لوحة الطالب فارغة وتدعم إضافة المقررات والشابترات وتعديل أسمائها وحذفها وتتبع المراجعة. تُحفظ البيانات تلقائيًا في localStorage للمتصفح الحالي، وتبقى عند مغادرة اللوحة أو إعادة التحميل. لا تتزامن بين الأجهزة أو بين الموقع المحلي والموقع المنشور. حذف بيانات الموقع يمسحها، وقد يحذف المتصفح الخاص البيانات عند إغلاقه. تظهر رسالة عند تعذّر القراءة أو الحفظ، ولا تُستبدل البيانات التالفة تلقائيًا.

تشغيل اختبارات التخزين: `npm test`.

يمكن البحث باسم المقرر أو عنوان أي شابتر داخله، ثم البحث داخل المقرر وتصفية الشابترات إلى الكل أو للمراجعة أو تمت المراجعة. البحث يتجاهل التشكيل العربي واختلافات الألف وحالة الأحرف الإنجليزية. تظل إحصاءات التقدم محسوبة من جميع البيانات، وتستهدف عمليات التعديل والحذف الشابتر الصحيح حتى أثناء التصفية. يشمل `npm test` اختبارات البحث أيضًا.
