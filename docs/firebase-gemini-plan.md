# خطة StudyMate لاستخدام Firebase وGemini

تاريخ الخطة: 2026-09-08. المرجع: IEEE SRS الإصدار 1.1 في `output/srs`.

## القرار

تحديث 2026-09-13: نجح استدعاء Firebase AI Logic بهوية الخادم؛ كُشف قبول مفتاح الويب للتوليد المباشر وعولج باستثناء خدمة AI Logic من خدماته المسموحة. أُثبت رفض المفتاح بعدها واستمرار نجاح الخادم. راجع `firebase-ai-setup.md` للأدلة وحدود الاختبار؛ لم يُختبر طلب بجلسة طالب فعلية، والإنتاج لم يُفعّل.

يستخدم Gemini عبر **Firebase AI Logic** لتوليد الشرح والملخصات والاختبارات. استدعاء Gemini مباشرة خارج Firebase AI Logic لا يحقق هذا القرار. هذه خطة مستهدفة؛ لم ينفذ ربط Firebase أو Gemini ضمن تحديث المستندات.

Firebase Authentication للحسابات، وCloud Storage for Firebase لملفات PDF. تبقى ASP.NET Core للملكية والحصص والتحقق والتصحيح، وSQL Server للمقررات والنتائج والمحاولات والأهداف. يؤجل Firestore.

## المسار المستهدف

الموقع أو الجوال ← ASP.NET Core ← Firebase AI Logic ← Gemini، مع رجوع الناتج الكامل للخادم وحده قبل حفظه وإرسال النسخة المناسبة للطالب.

هذا المسار الخادمي **مرشح يتطلب إثباتًا تقنيًا**. توثيق AI Logic يركز على مكتبات العميل، ويوثق REST لتوليد المحتوى بقوالب الخادم. وجود القالب على الخادم لا يمنع وصول إجابته إلى مستدعيه. لذلك لا نفترض أن نقل القالب وحده يحمي مفاتيح الاختبار.

## عقد توليد المحتوى

- يرسل العميل معرّف الشابتر والنوع واللغة ومفتاح منع التكرار. الخادم يتحقق من الملكية ويقرأ النص ذي أرقام الصفحات.
- الشرح والملخص مخرجان مستقلان بالعربية أو الإنجليزية، مع المصطلحات المهمة ومراجع الصفحات والاقتباسات القابلة للتحقق.
- الاختبار يحتوي افتراضيًا عشرة أسئلة من اختيار متعدد وصح وخطأ؛ لكل سؤال خيارات وإجابة صحيحة واحدة وتفسير ومراجع.
- يحفظ الخادم النسخة الكاملة، ولا يرسل الإجابات الصحيحة أو تفسيراتها للطالب قبل التسليم. التصحيح عملية حتمية في الخادم ولا يستدعي Gemini من جديد.
- يرفض JSON غير المطابق أو الناتج المقطوع أو المحجوب. تعاد حصة الطالب عند الفشل، لكن قد تبقى تكلفة استدعاء المزود.
- يحفظ مع الناتج اسم النموذج وإصدار القالب والمصدر واللغة. لا تكتب النصوص الخاصة أو رموز الحساب في سجلات التشغيل.
- تبقى حدود PDF والحصة والمهل في SRS؛ OCR خارج نطاق التجربة. تعطل أدوات البحث الخارجي لهذه المهام وتختبر مقاومة تعليمات الحقن داخل PDF.

## ترحيل البيانات

1. أخذ نسخة احتياطية وجرد الحسابات والملفات والمخرجات.
2. اختبار توافق استيراد كلمات المرور إلى Firebase؛ استخدام إعادة التعيين عند عدم التوافق، مع منع دمج الحسابات بالبريد وحده دون إثبات الهوية.
3. إضافة ربط FirebaseUid فريد مع الحفاظ على معرّفات SQL والعلاقات الحالية.
4. نقل الملفات والتحقق من العدد والحجم والبصمة، مع سجل عمليات وتنظيف متكرر لأن SQL وStorage ليسا معاملة واحدة.
5. الحفاظ على النتائج السابقة وهوية مزودها الفعلية. لا يعاد تصنيف نتائج OpenAI القديمة كأنها Gemini.
6. بعد التحويل تمر الطلبات الجديدة عبر Firebase AI Logic. الرجوع يعطل التوليد الجديد ويتيح الأرشيف؛ لا يرجع تلقائيًا إلى مزود آخر.

## التشغيل والقبول

يتطلب Cloud Storage خطة Blaze وحساب فوترة. تنبيهات الميزانية لا تمثل سقف إنفاق؛ تضبط حصص المزود وحدود الطلبات ومفتاح إيقاف التوليد من الخادم. يحدد نموذج Gemini المتاح وإصداره بعد فحص دعمه للمخرجات المنظمة، دون تثبيت اسم غير مجرب.

تختبر عينة SRS من عشرين شابترًا نصيًا بالعربية والإنجليزية، مع مراجعة بشرية للمراجع وصحة مفاتيح الإجابة. سلامة JSON وحدها لا تثبت صحة الشرح. تشمل الاختبارات أيضًا انتهاء الجلسة والخروج وتعطيل الحساب، وفصل بيانات طالبين، والضغط المزدوج و429 والمهلة والحذف أثناء التوليد واسترجاع النسخ.
